# Code Review: Embed Image (base64) Feature

## Summary

The feature is well-structured and follows the existing MVVM patterns. Below are identified issues ranked by severity, from bugs to performance to polish.

---

## 1. Bug: TIFF filter missing from file dialog

**File:** `Views/MarkdownEditorView.xaml.cs:348`

The feature description lists `tiff` as a supported format, but the `OpenFileDialog` filter omits `*.tiff;*.tif`. ImageSharp supports TIFF, so adding it is trivial.

```csharp
// Current
Filter = "Images|*.png;*.jpg;*.jpeg;*.gif;*.bmp;*.webp"
// Fix
Filter = "Images|*.png;*.jpg;*.jpeg;*.gif;*.bmp;*.webp;*.tiff;*.tif"
```

---

## 2. Performance: UI thread blocked during image encoding

**File:** `Views/MarkdownEditorView.xaml.cs:357`

`ImageEmbedder.EncodeFile()` decodes, resizes, and re-encodes the image synchronously on the UI thread. For a 1600px WebP encoding with `BestQuality` method, this can take 2-5 seconds — the UI freezes.

**Fix:** Make `EncodeFile` async and run on a background thread, then marshal back to UI:

```csharp
private async void OnRequestEmbedImage()
{
    // ... file dialog ...
    string dataUri;
    try
    {
        dataUri = await Task.Run(() => ImageEmbedder.EncodeFile(dlg.FileName));
    }
    catch (Exception ex) { /* ... */ }
    // ... rest of insertion ...
}
```

---

## 3. Performance: `WebpEncodingMethod.BestQuality` is unnecessarily slow

**File:** `Services/ImageEmbedder.cs:31`

`BestQuality` (= Level 6) is the slowest WebP encoding method. For lossy q80, the visual difference vs `Level4` is negligible, but encoding is ~2-3x faster.

**Fix:** Change to `WebpEncodingMethod.Level4` (good speed/quality tradeoff).

---

## 4. Performance: Regex recompiled on every `Parse()` call

**File:** `Services/EmbeddedImagesBlock.cs:60`

The regex `@"^\[img-(\d+)\]:\s*(data:image/[^\s]+)$"` is created fresh each call. `Parse()` is called on every folding timer tick (1.5s) and on every embed operation.

**Fix:** Cache as a static compiled regex:

```csharp
private static readonly Regex EntryPattern = new(
    @"^\[img-(\d+)\]:\s*(data:image/[^\s]+)$",
    RegexOptions.Compiled);
```

---

## 5. Performance: Full document string replacement on embed

**File:** `Views/MarkdownEditorView.xaml.cs:385`

`Document.Replace(0, withRef.Length, updated)` replaces the **entire** document text. For a document with embedded images (potentially megabytes of base64), this is very expensive — it copies the entire string, invalidates all AvalonEdit data structures, and causes potential flickering.

**Fix:** Only replace the embedded-images block region:

```csharp
// Instead of replacing the whole document, compute the block region
// and replace only that portion.
var (images2, bs, be) = EmbeddedImagesBlock.Parse(withRef);
if (bs >= 0)
{
    var newBlock = /* rebuild block from images + new entry */;
    MarkdownTextEditor.Document.Replace(bs, be - bs, newBlock);
}
```

This requires refactoring `EmbeddedImagesBlock` to expose a `BuildBlock` method or accept an `ITextSource` / `TextDocument` directly.

---

## 6. Performance: `Parse()` scans entire document on every folding tick

**File:** `Services/MarkdownFoldingStrategy.cs:120`

`EmbeddedImagesBlock.Parse(docText)` runs `document.Text` (allocates full string copy including all base64 data) then `IndexOf` + regex on every 1.5s tick.

**Fix:** Short-circuit by checking for the start marker with `document.IndexOf` first, or cache the block region and only re-parse when the block region changes.

## 7. Correctness: `FormatSize` KB loses precision

**File:** `Services/ImageEmbedder.cs:43`

```csharp
if (byteLength < 1024 * 1024) return (byteLength / 1024) + " KB";
```

Integer division: `1535 / 1024 = 1 KB` instead of `1.5 KB`. Should be consistent with the MB branch:

```csharp
if (byteLength < 1024 * 1024) return (byteLength / 1024.0).ToString("0.0") + " KB";
```

## 8. Robustness: No size limit warning for embedded images

**File:** `Views/MarkdownEditorView.xaml.cs`

A user can embed a 10MB image (after resize + WebP encoding), resulting in ~13MB of base64 in the document. This makes the document slow to edit, save, and load.

**Fix:** After encoding, check the base64 size and warn if it exceeds a threshold (e.g., 2 MB):

```csharp
var sizeMB = dataUri.Length / (1024.0 * 1024.0);
if (sizeMB > 2.0)
{
    var result = MessageBox.Show(
        $"The encoded image is {sizeMB:F1} MB. Large embeddings may slow editing.\n\nEmbed anyway?",
        "Large Image", MessageBoxButton.YesNo, MessageBoxImage.Warning);
    if (result != MessageBoxResult.Yes) return;
}
```

## 9. Polish: No undo grouping for the two-step edit

**File:** `Views/MarkdownEditorView.xaml.cs:376-388`

The reference insertion and block upsert are separate undo operations. Pressing Ctrl+Z once only undoes the block update, leaving an orphaned `![alt][img-1]` reference.

**Fix:** Wrap both edits in an undo group:

```csharp
MarkdownTextEditor.Document.BeginUpdate();

    // upsert block

finally
{
    MarkdownTextEditor.Document.EndUpdate();
}
```

## 12. Edge case: `BuildBlock` has no trailing newline

**File:** `Services/EmbeddedImagesBlock.cs:129-130`

`BuildBlock` ends with `sb.Append(EndMarker)` without a trailing `\n`. If any text follows the block (unlikely in normal use), it would be on the same line as the end marker. The `Upsert` method appends the block after `TrimEnd()`, so in practice the next line starts clean, but adding a trailing newline is more robust.

### Implementation details — file by file

#### A. `Services/ImageEmbedder.cs` — Add `EncodeStream` overload

The existing `EncodeFile(string filePath)` loads from disk. A new `EncodeStream(Stream stream, string? sourceName = null)` overload reuses the same resize+WebP logic but accepts any `Stream` (memory stream from clipboard, etc.).

```csharp
public static string EncodeStream(Stream stream, string? sourceName = null)
{
    using var image = Image.Load(stream);

    const int maxSide = 1600;
    if (image.Width > maxSide || image.Height > maxSide)
    {
        image.Mutate(x => x.Resize(new ResizeOptions
        {
            Mode = ResizeMode.Max,
            Size = new Size(maxSide, maxSide)
        }));
    }

    var encoder = new WebpEncoder
    {
        FileFormat = WebpFileFormatType.Lossy,
        Quality    = 80,
        Method     = WebpEncodingMethod.Level4   // issue #3 fix
    };

    using var ms = new MemoryStream();
    image.Save(ms, encoder);
    var b64 = Convert.ToBase64String(ms.ToArray());
    return "data:image/webp;base64," + b64;
}
```

Then refactor `EncodeFile` to call `EncodeStream`:

```csharp
public static string EncodeFile(string filePath)
{
    using var fs = File.OpenRead(filePath);
    return EncodeStream(fs);
}
```

This eliminates code duplication and ensures both paths benefit from any future encoding changes.

**2.** Extract a shared `InsertEmbeddedImage(string dataUri, string altText)` private method from `OnRequestEmbedImage` to avoid duplicating the reference-insertion + block-upsert + undo-group logic. Both handlers will call this after obtaining the data URI.

```csharp
private void InsertEmbeddedImage(string dataUri, string altText)
{
    var current = MarkdownTextEditor.Text;
    var parsed  = EmbeddedImagesBlock.Parse(current);
    var id      = EmbeddedImagesBlock.NextId(parsed.images);

    MarkdownTextEditor.Document.BeginUpdate();
    try
    {
        var insertion = $"![{altText}][{id}]";
        var caret = MarkdownTextEditor.CaretOffset;
        MarkdownTextEditor.Document.Insert(caret, insertion);
        MarkdownTextEditor.CaretOffset = caret + insertion.Length;

        var withRef = MarkdownTextEditor.Text;
        var updated = EmbeddedImagesBlock.Upsert(withRef, id, dataUri);
        if (updated != withRef)
        {
            var keepCaret = MarkdownTextEditor.CaretOffset;
            MarkdownTextEditor.Document.Replace(0, withRef.Length, updated);
            if (keepCaret <= MarkdownTextEditor.Document.TextLength)
                MarkdownTextEditor.CaretOffset = keepCaret;
        }
    }
    finally
    {
        MarkdownTextEditor.Document.EndUpdate();
    }

    MarkdownTextEditor.Focus();
}
```

**4.** Add the new clipboard handler:

```csharp
private async void OnRequestEmbedImageFromClipboard()
{
    if (!Clipboard.ContainsImage())
    {
        MessageBox.Show(
            "No image found on the clipboard.\n\nCopy an image first (e.g. screenshot, Ctrl+C on an image).",
            "Embed from clipboard",
            MessageBoxButton.OK,
            MessageBoxImage.Information);
        return;
    }

    var bitmapSource = Clipboard.GetImage();
    if (bitmapSource == null)
    {
        MessageBox.Show("Could not read the clipboard image.",
            "Embed from clipboard", MessageBoxButton.OK, MessageBoxImage.Warning);
        return;
    }

    // Convert WPF BitmapSource → PNG MemoryStream → ImageSharp
    string dataUri;
    try
    {
        var encoder = new System.Windows.Media.Imaging.PngBitmapEncoder();
        encoder.Frames.Add(System.Windows.Media.Imaging.BitmapFrame.Create(bitmapSource));

        using var pngStream = new System.IO.MemoryStream();
        encoder.Save(pngStream);
        pngStream.Position = 0;

        dataUri = await Task.Run(() => ImageEmbedder.EncodeStream(pngStream));
    }
    catch (Exception ex)
    {
        MessageBox.Show($"Could not embed clipboard image: {ex.Message}",
            "Embed from clipboard", MessageBoxButton.OK, MessageBoxImage.Error);
        return;
    }

    InsertEmbeddedImage(dataUri, "clipboard-image");
}
```

**Key WPF details for the implementer:**
- `Clipboard.ContainsImage()` checks if the clipboard holds a `BitmapSource`-compatible format (works for screenshots, browser image copies, etc.).
- `Clipboard.GetImage()` returns a `BitmapSource` in DIB format — it's not directly consumable by ImageSharp. The intermediate `PngBitmapEncoder` step converts it to PNG bytes that `Image.Load()` can read.
- The `pngStream.Position = 0` reset is critical — `Image.Load()` reads from the current position.
- `Clipboard` must be called on the UI thread (WPF requirement). The `await Task.Run()` only offloads the ImageSharp encoding, not the clipboard access.

## 14. Feature: Preview TOC Navigation (Slide-in Sidebar + Scroll-spy)

### Goal

Add a premium, slide-in TOC navigation panel to the **browser preview** so users can see the document's heading structure at a glance, click any heading to jump to it, and see which heading they're currently reading (scroll-spy).

### Architecture context

The preview is a pure HTML page served by `PreviewHttpServer` and opened in the user's default browser. It has no WPF controls — everything is client-side HTML/CSS/JS inside the template returned by `HtmlTemplateService.GetLiveTemplate()`. Therefore, **this feature requires zero C# changes** — only modifications to the HTML template string in `HtmlTemplateService.cs`.

### UX Design

**Floating toggle button (FAB):**
- Position: fixed, top-left corner (`top: 16px; left: 16px`)
- Icon: ☰ (hamburger) when closed, ✕ when open
- 40×40px circle with semi-transparent dark background
- Subtle hover effect (scale + brightness)
- Keyboard shortcut: press `T` to toggle (only when no input/textarea is focused)

**Slide-in sidebar:**
- Slides in from the left with a CSS `transform: translateX()` transition (300ms ease-out)
- Width: 280px on desktop
- Glassmorphic background: `backdrop-filter: blur(16px) saturate(180%)` with semi-transparent white `rgba(255,255,255,0.82)` — gives a frosted-glass look that blends with any content
- Border-right: 1px solid `rgba(0,0,0,0.08)`
- Box-shadow for depth

**Header inside sidebar:**
- Title: "OUTLINE" in small caps, muted color, with a heading count badge (e.g., "12 headings")
- Padding: 16px top, 12px horizontal

**Heading items:**
- Each heading shown as a clickable item with:
  - **Indentation**: `padding-left: 12px + (level - 1) * 16px` — creates a clear hierarchy
  - **Level indicator**: 3px-wide colored left border, color varies by level:
    - H1: `#6366F1` (indigo — primary accent)
    - H2: `#7C7FEE`
    - H3: `#9295F0`
    - H4+: `#B4B6F5`
  - **Text**: truncated with ellipsis if too long, font-size 13px, line-height 1.5
  - **Hover**: background highlight `rgba(99,102,241,0.06)` + slightly bolder text

**Scroll-spy (active heading):**
- As the user scrolls, the heading closest to the viewport top is detected via `IntersectionObserver` with `rootMargin: "-80px 0px -60% 0px"` (prioritize headings near the top)
- Active heading item gets:
  - **Bold text** (`font-weight: 600`)
  - **Accent left border** (`#6366F1`, 3px, full height)
  - **Background highlight** `rgba(99,102,241,0.08)`
  - **Text color** changes to `#6366F1`
- The sidebar auto-scrolls to keep the active item visible (`scrollIntoView({ block: 'nearest', behavior: 'smooth' })`)

**Click behavior:**
- Clicking a heading smooth-scrolls the main content to that heading
- Uses `scrollIntoView({ behavior: 'smooth', block: 'start' })` with a 60px scroll offset to account for any fixed elements
- On viewport < 768px: sidebar auto-closes after click (mobile-friendly)

**Responsive:**
- `< 768px`: sidebar becomes full-width overlay with semi-transparent backdrop
- `>= 768px`: sidebar sits alongside content, content is NOT shifted (overlays with glassmorphic effect)

**Print:**
- Sidebar and FAB hidden via `@media print` rule

### Implementation — `Services/HtmlTemplateService.cs`

All changes go into the `LiveTemplate` string constant. There are three injection points: **CSS**, **HTML**, and **JS**.

#### A. Add heading `id` attributes (JS — modify existing heading renderer)

The current custom `heading()` renderer only adds `data-source-line` but no `id`. We need `id` attributes for anchor navigation. Modify the renderer:

```javascript
var _headingSlugs = {};
heading(token) {
    _sourceLine++;
    var text = this.parser.parseInline(token.tokens);
    // Generate a slug for the id attribute
    var slug = text.toLowerCase()
        .replace(/<[^>]+>/g, '')           // strip HTML tags
        .replace(/[^\w\u00C0-\u024F]+/g, '-')
        .replace(/^-+|-+$/g, '');
    // Deduplicate
    if (_headingSlugs[slug] !== undefined) {
        _headingSlugs[slug]++;
        slug = slug + '-' + _headingSlugs[slug];
    } else {
        _headingSlugs[slug] = 0;
    }
    return '<h' + token.depth + ' id="' + slug + '" data-source-line="' + _sourceLine + '">' + text + '</h' + token.depth + '>';
},
```

Also reset `_headingSlugs = {}` in `renderContent()` alongside `_sourceLine = 0`.

function buildToc() {
    var headings = document.querySelectorAll('#content h1, #content h2, #content h3, #content h4, #content h5, #content h6');
    _tocList.innerHTML = '';
    var count = 0;
    headings.forEach(function(h) {
        count++;
        var li = document.createElement('li');
        var a  = document.createElement('a');
        a.href = '#' + (h.id || '');
        a.setAttribute('data-level', h.tagName.charAt(1));
        a.textContent = h.textContent;
        a.addEventListener('click', function(e) {
            e.preventDefault();
            var target = document.getElementById(h.id);
            if (target) {
                var y = target.getBoundingClientRect().top + window.scrollY - 60;
                window.scrollTo({ top: y, behavior: 'smooth' });
            }
            // Auto-close on mobile
            if (window.innerWidth < 768 && _tocOpen) toggleToc();
        });
        li.appendChild(a);
        _tocList.appendChild(a); // <a> is block-level, no <li> wrapper needed for simplicity
    });
    _tocCount.textContent = count + (count === 1 ? ' heading' : ' headings');
    setupScrollSpy();
}

// ── Scroll Spy ─────────────────────────────────────────────
var _scrollObserver = null;

function setupScrollSpy() {
    if (_scrollObserver) _scrollObserver.disconnect();
    var headings = document.querySelectorAll('#content h1, #content h2, #content h3, #content h4, #content h5, #content h6');
    if (!headings.length) return;

    var options = {
        root: null,
        rootMargin: '-80px 0px -60% 0px',
        threshold: 0
    };

    _scrollObserver = new IntersectionObserver(function(entries) {
        entries.forEach(function(entry) {
            if (entry.isIntersecting) {
                setActiveHeading(entry.target.id);
            }
        });
    }, options);

    headings.forEach(function(h) { _scrollObserver.observe(h); });
    updateActiveHeading();
}

function updateActiveHeading() {
    var headings = document.querySelectorAll('#content h1, #content h2, #content h3, #content h4, #content h5, #content h6');
    if (!headings.length) return;

    var active = null;
    var threshold = window.scrollY + 100;
    for (var i = headings.length - 1; i >= 0; i--) {
        if (headings[i].getBoundingClientRect().top + window.scrollY <= threshold) {
            active = headings[i];
            break;
        }
    }
    setActiveHeading(active ? active.id : headings[0].id);
}

function setActiveHeading(id) {
    var links = _tocList.querySelectorAll('a');
    var found = false;
    for (var i = 0; i < links.length; i++) {
        var isActive = links[i].getAttribute('href') === '#' + id;
        links[i].classList.toggle('active', isActive);
        if (isActive && !found) {
            found = true;
            // Auto-scroll TOC to keep active item visible
            links[i].scrollIntoView({ block: 'nearest', behavior: 'smooth' });
        }
    }
}

// Also update active heading on scroll (fallback for fast scrolling past observer)
var _scrollSpyRaf = null;
window.addEventListener('scroll', function() {
    if (!_tocOpen) return;
    if (_scrollSpyRaf) cancelAnimationFrame(_scrollSpyRaf);
    _scrollSpyRaf = requestAnimationFrame(updateActiveHeading);
}, { passive: true });
